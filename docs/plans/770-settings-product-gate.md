# #770 Gate 1 — 设置页按用户坐标系重做

> 输入：`770-settings-audit-2026-09-15.md`（缺陷与根因）+ co-creator 2026-09-16/17 的方向（"只露出用户真正要决定的少数几项；一个数据目录就够"）+ 08-31 spec。
> 原则：**一个设置出现在产品里，必须同时满足**——用户能看懂（人话、人类单位、不出现变量名）、改了真生效（或诚实显示为何不生效）、形态等于可用性（状态显示成状态，别伪装成控件）。

## 现状

28 项 / 25 项可编辑。其中 24 项需完整重启才生效，5 个目录行、6 个以秒为单位的 TTL、3 个用冒号拼接的目录列表字符串。

## 一、状态区：用户需要**看到**，但不做决定

按外部用户 issue 的痛点排序（#473 / #1250 丢数据、#1132 / #1135 路径分裂、#1062 改了不生效）：

| 显示什么 | 为什么是它 | 数据来源 |
|---|---|---|
| **存储模式：持久化 / 内存** + 内存模式下醒目警告 | 最贵的一次事故：外部用户静默跑内存模式一整天，重启后全丢（#1250） | `MEMORY_STORE` / `REDIS_URL`（现已只读） |
| **数据存在哪** | 文档、页面、脚本曾给出三个不同答案 | `DATA_DIR` 实际解析值 |
| **当前访问地址与端口** | 端口常被启动器/`.env.local` 覆盖，页面显示的值不等于生效值 | 运行时实际值 |
| **待重启项**：已保存 X / 当前生效 Y | "改了不生效"的根源（#1062） | `savedValue` vs `currentValue`（已实现） |
| **所有者模式**：单用户本地 / 已设锚点 | 锚点语义反向开门，用户需知道自己处于哪种 | `DEFAULT_OWNER_USER_ID`（只读，已有理由） |
| **平台状态目录** | 与数据目录区分，避免再问"我的账号配置在哪" | `CAT_CAFE_DATA_DIR`（只读） |

## 二、决策区：用户真正要做的选择（**5 个**）

| 决策 | 取代原来的 | 生效方式 |
|---|---|---|
| **① 数据存放位置** | `DATA_DIR` + `CACHE_DIR` + `ANNOTATION_DATA_DIR` 三个目录行 | 改则迁移（现状已是"没配就 fallback、配了才搬"，保留） |
| **② 允许从手机/局域网访问** | `API_SERVER_HOST` + `CORS_ALLOW_PRIVATE_NETWORK` 两个变量 | 一个开关同时写两者；#1298 的 HTTP 崩溃要一并处理 |
| **③ 数据保留** | 6 个以**秒**为单位的 TTL | 默认"永久保留"；选自定义才展开，单位用天 |
| **④ 日志详细程度** | `LOG_LEVEL` | 已改为即时生效 |
| **⑤ 猫能访问哪些目录** | `PROJECT_ALLOWED_ROOTS` + `_APPEND` + `DENIED_ROOTS` 三个冒号拼接字符串 | 列表 UI + 目录选择器；allow/deny 变成模式而非三个旋钮 |

## 三、隐藏：保留 `.env` 可改，不进产品界面

`API_SERVER_PORT` / `FRONTEND_PORT` / `PREVIEW_GATEWAY_PORT`（启动器常覆盖，显示为状态即可）、`FRONTEND_URL`（反代）、`PREVIEW_GATEWAY_ENABLED`、`MAX_A2A_DEPTH`、`REDIS_KEY_PREFIX`、`DOCS_ROOT`、`CLI_TIMEOUT_MS`（名实不符，见 #854，语义修正前不进界面）。

出口是右上角「打开 .env ↗」。**每一项隐藏都要写明理由**——"没理由的只读"仍然禁止。

## 四、结果

**28 个旋钮 → 6 项状态 + 5 个决策**，目录行 5 → 1。

## 五、状态矩阵（Gate 2 设计必须覆盖）

- 部署：worktree dev / runtime / desktop（desktop 写 `.env` 不被读，需显式降级提示）
- 身份：owner / 非 owner（敏感项写入需 owner）
- 数据：loading / 正常 / 被 `.env.local` 遮蔽 / 待重启 / 此部署方式下不可用

## 六、不在本轮范围

模型接入配置的可理解性（外部用户第一痛点，~14 个 issue，但不在这一页）——另立 feature。
