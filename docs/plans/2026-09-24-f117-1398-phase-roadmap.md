# F117 / #1398 推进路线（2026-09-24 起）

> 维护：布偶猫 opus（实现）· 缅因猫 sol（交叉审查）· 缅因猫 astra（架构讨论，本路线审核）
>
> 每合入一个 PR，就更新本文的进度表。这条工作线的进度以本文为准，不以聊天记录为准。

## 为什么有这份路线

2026-09-24 起，吴浪出行约半个月，由 clowder-ai maintainer Landy 代为照看。Landy 和 opus 在
thread `thread_msr51149hym0i79f` 对齐后（消息 `…1279`、`…1294`、`…1299`、`…1304`），改用下面的推进方式。

## 约定

1. **按 phase 推进，一个 phase 一个 PR。** 一个 phase 可以有多个 commit，但只提一个 fork PR，合进
   develop_base（也就是 3001 运行的版本），合入即闭环。不要拆得太碎。
2. **直接在 3001 体验。** 不再做 worktree 隔离体验。合入 develop_base 后，由 Landy 重启 3001，在真实使用中
   体验。合入之前，由猫补齐把关：相关测试全量通过，sol 交叉审查通过。合入时保留回退点（合入前的 develop_base
   commit），出问题一步退回。
3. **每个 phase 开工前先写一页设计，** 和 Landy 对齐产品和体验，再写代码。
4. **审查不做防御性加码。** 审查盯正确性和用户能看到的行为。同一个 phase 审到第 3 轮还没收敛，就停下来找
   Landy 对齐，不在猫之间来回拉锯。
5. **每个 PR 合入后，更新本文的进度表。**
6. **决策分工。** 技术决策以吴浪（clowder-ai 架构师）已有的决定为准，见 F117 文档的 Key Decisions；产品、
   愿景和体验由 Landy 给反馈。需要拍板时直接 @ Landy。
7. **上游不拆 PR。** fork 这边体验没问题后，上游发一个新版本并冻结合入；#1398 rebase 到最新，启动上游开源
   版本体验；确认没问题，再以一个 PR 合入。
8. **分工。** opus 实现，sol 交叉审查，astra 负责架构讨论和本路线的审核。Fable 暂不参与。
