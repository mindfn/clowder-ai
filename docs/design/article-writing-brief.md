# Writing Brief v3（换坐标系）

## 废止的旧假设

以下 v2 约束被证明是"浅"的制造者，废止：

- ~~一个承重问题必须压进一个短段/短节~~ → 一节仍只回答一个读者问题（焦点保留），但允许用事件、机制、图、边界和失败方式完整展开；
- ~~历史一页以内 / 第一篇不进设计推导~~ → 第一篇分类从真实故事里抽出，不再悬空；
- ~~不设图配额上限的反面（图只做总览）~~ → 图承担解释，不做目录；
- ~~文风只禁表面模板~~ → 升级为段落动作审查（见下）；
- ~~不设硬字数~~ 保留，但截断标准改为"承重问题是否被例子、机制和边界讲透"。

不变的底线（v2 继承）：来源精确链接与 audit 档位、三框架比较 caveat（"只覆盖列出的官方概念页，不证明实现能力缺席"）、证据三级表述（直接观察/机制推断/设计选择）、量词边界、事件级表述无频率量词、brand 隔离。

中心论点不变：第一篇——"当我们谈论 multi-agent，谈的不是界面上有几个角色，而是为了解决什么问题、有意识地拆开了什么，以及愿意付多少协调成本"；第二篇——"把几个月协作里反复发生的事故，逐步翻译成结果要求、状态模型、机制选择和可验证假设"。

## 工程博客声音（结构基准 + 段落动作审查）

Anthropic 四篇结构审计结论（sol 完成，source=use / decision-fit=direct，仅借组织方法）：**一篇只钉一个工程问题；先给现象与动作，再给抽象；例子承担论证，不做装饰；一个承重机制有自己的小节、图、边界和失败方式。**

段落动作审查（重写与 review 共用，替代纯 grep 禁词）：

| 病 | 检法 |
|---|---|
| 抽象名词连续做主语 | 段内主语清单：连续 2+ 段主语非"我们/具体系统/具体人"即标记 |
| 裁决句→三项列举→金句收尾的同构段 | 相邻段结构比对 |
| 段首"先/再/还有/所以"链 | 段首词扫描 |
| `不是 X 而是 Y`/破折号/冒号承担推理 | 每句一逻辑动作检查 |
| caveat 全堆尾部（正文像宣传、末尾像审计） | 证据边界必须贴着 claim 写 |
| 标题只说逻辑关系（"从 A 到 B"） | 标题必须点具体工程问题 |
| 裁判视角（"任何方案都应该"）/有机隐喻（"长出来"） | 视角与隐喻扫描 |

例句基准（lang 原句的最终改法，sol 版）：先事实后适用边界——"这四条不是我们先写好、再照着实现的。责任误归属、续接断链和静默失联反复出现后，我们才把检查标准收敛到这里。……别的方案不必长成我们的样子；中心编排或共享状态加锁，只要在相同约束下达到这些结果，也成立。"（"反复出现后"的时间因果若无账本坐标支撑，改无时间因果表述。）

## 第一篇：证据角色分工，不是案例堆

> ⚠️ **v4 重构（lang 2026-08-17 裁决 + sol 骨架 + 宪宪落账）见本节末《第一篇 v4 重构指令》。** 论证主轴从“故事 illustrate 分类”改为“问题（长期治理）→ 解法（Clowder-AI 为何这样设计）”；下方旧结构里的**账本坐标与证据上限仍有效**，但各故事**承重角色按 v4 重新分配**。

结构：用户问题 → 一词为何混用（压短）→ **真实协作故事（开写门槛：≥2 个独立事件族，其中 ≥1 条来自冷读产线之外；核验通过后至多四条）** → 从故事抽出四个拆分面 → 选择器与成本 → 引第二篇。

每条故事各承担一条论证，固定回答五问：**发生了什么 → 单 agent/较轻形态哪里不够 → 我们实际加了什么 → 观察到什么 → 付了什么成本**。故事数与族构成由下方账本的核验结果决定，不预设；lang 硬要求——**第一篇必须含冷读之外的真实例子**——由开写门槛强制（见"诚实选材与开写门槛"）。

### 第一篇 v4 重构指令（lang 2026-08-17 裁决 + sol 骨架；宪宪落账，supersede 上文旧结构的“角色分工”与“构成锁定”）

**为什么重构**：旧稿把“长期团队的必要性”主要压在审稿/冷读例子上——但那些例子证明的是“独立视角有价值”，不是“为什么需要跨会话的责任治理”，证据对象与论点错位；标题也只承诺“泛谈 multi-agent”，没承诺读者最终会拿到的答案。

**读者读完必须拿到**（lang）：① Clowder-AI 与其它几种 multi-agent 的区别；② 它为什么这样设计、在解决什么问题；③ 如何自评一个任务是否需要 multi-agent / 哪一层。

**新主轴（问题 → 解法）**：
1. 用户两问（保留）→ 一词几个时代（压短，保留）。
2. 四种做法：**用“同一篇文章”这一个例子**完成概念辨析（persona / subagent / agent team / 长期团队）。
3. **选型总裁决**（四种做法收束句，公共分类到此结束，sol 原句）：> 不要先问哪一种更高级，而要问任务需要拆开什么：只需改变方法，用 persona 或 skill；需要并行和隔离上下文，用 subagent；需要多个主体在一次任务中直接协作，用 agent team；当责任、授权和交接必须跨会话持续时，才需要长期团队。四者可以组合，默认选择满足要求的最轻组合。
4. **换一个真正需要长期治理的工作**（不再复用审稿例子）：一件跨天、需求会变、会话会结束、执行者会换手、失败后还要继续的工作。**承重事件 = 承诺掉球（候选 b，L104，已核冷读外责任连续族，thread_mrdip0u5aw4ysi97）**——证据已在账本，无需新造软件交付 saga。
5. 前三形态能加方法/容量/任务内协作，但**不天然回答**治理四问：**现在谁负责 / 谁有权批准 / 换手后谁继续 / 事后如何追溯**（这四问＝“责任 + 授权”两个拆分面的具体化）。
6. 引出 Clowder-AI：面向的不是单次复杂任务，而是目标持续演化、跨天跨会话、多主体（人+猫）共同判断、需要责任与授权连续性的工作。
7. 我们的解决方向：稳定成员、共享真相源、持久工作项、责任与授权分离、可验证交接。
8. 四个拆分面 + **普适/特有脊柱点破**：能力两面（执行上下文、协作关系）行业普遍在做、我们多半是使用者；治理两面（责任、授权）才是我们特有、要解决的核心。（caveat：协作关系里“独立性来自隔离上下文而非提示词”这条洞见是我们强调的，属半特有，别一刀切成纯普适。）
9. 选择器（何时该用，保留）→ 引第二篇。

**故事重新配角**（supersede L108 锁；账本坐标与证据上限全部不变，只改承重角色）：
- **承重** = 承诺掉球（候选 b）：扛“为什么需要长期责任治理”。
- **降为 cameo**（“长期团队内部也组合使用轻量机制”，不再扛 Clowder-AI 必要性主论证）：冷读/独立质疑、会话恢复（候选 a）、并行复核（04 月文档线）。
- 证据上限纪律不变：不把单 reader 标成并行容量、不把 transcript 恢复标成责任连续、不把 review fan-out 标成并行施工、不把兜底任务标成“此后不再掉球”。

**措辞规则**（lang 点 1 + sol）：全篇清洗“买 / 付钱 / 划算 / 买的是”→“收益 / 成本 / 代价 / 增加的是 / 值得采用 / 适用条件”。例：你买的是三类东西 → multi-agent 主要带来三类收益；买这些都要付钱 → 这些收益也伴随明确成本。

**边界措辞**（sol；守住不越界）：不写“既有产品都不具备这些能力”。准确说法：> persona、subagent 和 agent team 本身不保证这组长期责任契约；其他框架也可能通过应用代码或外部控制面补足。Clowder-AI 的选择，是把它直接放在平台中心。

**标题**（lang 定，pending）：

## 人类阅读版式纪律（写进正文生产，非事后润色）

- H2 = 读者的大问题，H3 = 一个机制或一个事件；标题写具体工程问题，禁"从 A 到 B"式逻辑标签；
- 一段一个动作：现象、解释、选择、边界分开；
- 新概念首现 = 一句白话 + 一个具体对象，然后才给术语；
- 精确映射进表，状态变化进序列/时间线，因果与取舍留给 prose；
- 图前提读者问题，图后只讲最值得注意的关系，不朗读图中文字；
- caveat 贴着 claim 走；证据矩阵负责总账，不负责第一次纠偏；
- 允许留白、短段、不对称结构；不追求每节金句；
- 每节三遍检查：扫标题知路线 / 只看图表懂关系 / 通读懂为什么。
